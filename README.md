# 손목 위의 시계

Android Chrome에서 손목을 비추고 3D 시계를 착용해 보는 웹 프로토타입입니다.

**실행 주소:** https://bluewhale127.github.io/wrist-try-on/

## 휴대폰에서 사용하기

1. Android Chrome에서 위 주소를 엽니다.
2. **카메라 시작**을 누르고 카메라 권한을 허용합니다.
3. 밝은 곳에서 **손끝까지 화면 안에 넣고 손등을 카메라와 평행하게 맞춘 뒤 약 2초 동안 멈춰** 주세요. 화면의 기준 확인이 끝나야 시계가 나타납니다. 조건이 부족하면 손끝·각도·움직임 안내에 맞춰 주세요. 방향이 반대로 붙으면 손등을 보인 상태에서 **손등 기준 맞추기**를 누릅니다. 다른 손으로 바꿀 때도 기준을 다시 맞춥니다.
4. 시계 크기, 착용 위치, 방향을 맞춥니다.
5. 준비한 시계가 있으면 **내 시계 불러오기**에서 `.glb`를 선택합니다.

카메라 영상과 선택한 시계 파일은 기기 안에서 처리하며 서버로 업로드하지 않습니다. 첫 페이지 접속 때 추적 모델 등 실행 파일을 다운로드합니다. 카메라를 끄거나 다른 탭/앱으로 이동하면 스트림을 종료합니다. 착용 조절 값은 모델별로 이 브라우저에 저장됩니다. 카메라 영상과 GLB 파일 자체는 저장하지 않습니다. 진단 기록은 사용자가 시작할 때만 좌표와 표시 상태를 메모리에 보관하고, 저장 버튼을 누르면 기기에 내려받습니다. 새로고침 후 GLB는 다시 선택해야 합니다.

## 기능

- 후면 카메라를 기본으로 사용하는 손목 위치·방향 추적
- 직접 만든 임시 시계와 GLB 모델 교체
- 크기, 손목 위 위치, 시계 회전, 모델 기울기·높이 조정
- 손목 뒤 스트랩을 가리는 근사 처리
- 카메라 권한 오류 안내와 추적 손실 시 시계 숨김

## 0.7.16 실제 Datejust 모델 검증

기존 0.7.12 추적 엔진을 유지하고 사용자 제공 GLB의 개발 검증 경로를 추가했습니다. **Datejust 검증 모델** 버튼 또는 `?model=datejust` 링크로 약 22MB 모델을 불러옵니다. VIVER AR에는 반영하지 않았습니다.

- GLB의 유리 네 재질을 웹용 투명 재질로 보정해 숫자판을 보이게 했습니다. 실물의 광학 굴절·날짜창 확대를 재현하는 렌더링은 아닙니다.
- 원본의 41mm 장면 표기를 기준으로 단위를 정리하고 케이스 중심·뒷면 접점을 메타데이터로 지정했습니다. 이 표기는 실제 손목 치수 측정을 의미하지 않습니다.
- 메타데이터가 없는 일반 GLB의 기존 정렬은 유지합니다. 원본 메시·텍스처와 고정된 브레이슬릿 형태를 보존하며, 손목 크기에 맞춘 자동 스트랩 변형은 하지 않습니다.
- 모델은 약 35.6만 삼각형/46개 메시 프리미티브입니다. 모바일에서 크기·가림·프레임 속도를 확인할 검증 버전이며 경량화는 아직 적용하지 않았습니다.

검증: 자동 검사 102개 및 빌드 통과. 브라우저에서 실제 GLB를 불러와 녹색 숫자판 표시를 확인하고, 통제된 카메라 관측에서 시계 모델 표시와 회전을 검사했습니다. 실제 Android 카메라 추적 정확도·성능은 휴대폰에서 확인해야 합니다.

## 0.7.12 후면 회전 정점 누락과 깊이 오차 처리

0.7.10의 검사는 연속된 이상적 관측에 치우쳐 있었습니다. 손을 180°까지 돌렸다 되돌리는 입력에서 정점의 관측 한 번만 없애도, 이전 코드는 `150° → 관측 없음 → 150°`를 `150° → 유지 → 210°`로 선택한 뒤 한 바퀴를 계속 그렸습니다. 두 깊이 출력에 15°의 같은 편향을 준 경우에도 기존 14° 허용 조건 밖으로 나가 보정이 작동하지 않았습니다. 이는 코드 반례이며 특정 휴대폰 녹화의 정확한 원인을 확정한 결과는 아닙니다.

- 후면에서 최근 회전 예측과 두 깊이 출력이 뚜렷하게 다른 후보를 지지하면 첫 충돌을 보류합니다. 정점의 관측이 빠지면 실제 역방향 이동량이 0일 수 있으므로, 역방향 이동량과 정면 근처라는 조건을 먼저 요구하지 않습니다.
- 두 깊이 출력의 상호 일치와 후보에 대한 약 34° 이내 오차, 다른 후보보다 뚜렷한 선호, 높은 투영 품질, 이어지는 관측을 함께 확인합니다. 두 출력은 같은 모델이며 독립적인 센서 증거가 아닙니다. 한 프레임의 잘못된 깊이만으로 반대로 돌리지 않습니다.
- 확인이 이미 이어지고 있을 때만 기존 회전 기억보다 늦게 확인을 완료할 수 있습니다. 관측 누락은 확인 횟수를 지우며, 시계 표시의 220ms 만료나 영상 보조의 유지 시간을 늘리지 않습니다. 보이지 않는 구간의 움직임을 새로 예측하지 않습니다.
- 전면, 첫 연결, 6·12시 정렬, 스트랩과 0.7.11의 기록 기능을 유지합니다.

검증: 자동 검사 98개와 빌드 통과. 양손·가로/세로·양방향·33/67/100ms 간격에서 정점 주변의 누락과 ±15/20° 깊이 편향을 조합한 600조건이 가짜 한 바퀴 없이 원위치로 돌아옵니다. 새 검사는 0.7.11에서 실패합니다. 기존 이상적 왕복 216조건과 단일 오류 거부 검사도 통과하며, 전면 840개 입력 결과는 0.7.11과 동일합니다. 실제 앱에서도 통제된 67ms 간격의 관측에서 180° 정점만 누락해, 잘못된 후보를 한 번 보류한 뒤 원위치로 복귀하고 회전·정지 구간 28프레임 모두 표시되는 것을 확인했습니다. 이 검사는 카메라·추론·시각을 대체한 입력 검증이며 실제 기기에서의 모든 회전 오류 해결을 보장하지 않습니다.

## 0.7.11 진단 기록 보존과 시계 표시 확인

- 관절 표시와 기록을 분리했습니다. **관절·회전 진단 → 진단 기록 시작**을 누르면 표시 선을 꺼도 기록합니다. 화면의 **시계 표시** 숫자는 카메라 모드에서 시계 본체를 표시한 렌더 표본 수입니다. 미리보기 시계는 포함하지 않습니다.
- 카메라 재시작·전환·기준 재설정으로 기록을 지우지 않습니다. 초기화 이유와 시간도 남깁니다. 최대 2분 또는 관측 3,600개/렌더 7,200개/이벤트 500개 한도에 닿으면 기록을 멈추며, 앞부분을 덮어쓰지 않습니다. 중지 후 이어서 기록할 수 있습니다. 새로고침하면 메모리의 기록은 사라집니다.
- 저장하면 기록을 멈추고 JSON을 내려받습니다. 기존 관측 `frames`에 더해, 실제 시계 렌더 상태·회전 `renders`(최대 초당 30개와 표시 상태 전환), 초기화/기록 구간 `events`, 시계 표시 수 `summary`, 기준 손 모양·선택 회전·속도 기억을 보존합니다. 영상이나 픽셀은 저장하지 않으며 자동 업로드하지 않습니다.
- 추적·초기 연결·회전 보정은 0.7.10과 같습니다. 실제 폰에서 계속 보고된 회전 문제는 아직 해결 여부를 판단할 자료가 부족합니다. 이 변경은 그 문제 구간을 확인하기 위한 기록 보완입니다.

검증: 자동 검사 95개와 빌드 통과. 통제된 카메라 입력을 사용하는 실제 앱에서 관절 표시를 끈 채 시계 연결·회전·카메라 재시작·다시 연결·JSON 저장을 확인했습니다. 두 구간의 관측 124개와 시계 표시 표본 72개가 함께 남았고, 표시 표본에는 모두 실제 렌더 회전이 포함됐습니다. 미리보기 오집계와 브라우저 오류는 없었습니다. 추적 관련 11개 모듈은 0.7.10과 동일합니다. 실제 Android에서의 기록 비용과 회전 문제는 후속 자료로 확인해야 합니다.

## 0.7.10 후면 빠른 왕복 회전 수정

빠르게 손바닥을 뒤집었다가 되돌릴 때 이전 회전 속도의 예측이 반대 깊이 후보를 선택하고, 이 선택을 다시 속도 기억에 넣어 시계가 한 바퀴 도는 오류를 수정했습니다. 정확한 가상 좌표를 약 15회/초로 넣어도 기존 코드는 `0→180→0°`를 `0→180→360°`로 선택했습니다.

- 후면에서 빠른 회전 직후, 정면에 가까웠던 자세를 기준으로 세계 좌표와 정규화 깊이가 함께 되돌림을 지지하면 첫 충돌에서는 이전 자세를 잠시 유지합니다. 같은 모델의 두 출력이므로 그 일치만 신뢰하지 않고 여러 입력에서 이어지는 동작을 확인합니다.
- 적어도 두 관측과 50ms의 확인 뒤 되돌아오는 후보를 채택하고 이전 방향의 속도 기억을 지웁니다. 확인 중에는 잘못된 후보를 새 속도 관측으로 누적하지 않습니다. 입력 사이 허용 움직임은 경과 시간에 따라 달라져 빠른 회전이 확인 기록을 매번 초기화하지 않도록 했습니다.
- 전면 경로, 초기 연결, 6시/12시 기준, 일반 회전 속도 제한, 세로 팔 기울기 보정과 영상 보조의 만료 시간은 유지합니다. 손가락이 사라진 뒤의 회전을 새로 예측하는 기능은 추가하지 않았습니다. 확인 상태는 진단의 `turnPending`/`turnRealigned`로 기록합니다.

검증: 전체 자동 검사 89개와 빌드 통과. 양손·양방향·가로/세로·33/67/100ms 간격·회전 폭/속도를 조합한 왕복 216개 조건에서 가짜 한 바퀴 회전과 표시 만료가 없었습니다. 단일 깊이 오류, 관측 중단, 두 깊이 출력의 불일치, 손바닥에서 멈추기도 검사했습니다. 새 왕복 검사는 수정 전 코드에서 실패했습니다. 전면 840개 입력의 수락 여부·회전·위치·크기·속도 기억·표시 상태는 0.7.9와 동일했습니다. 이는 통제된 입력 검사이며 실제 Android 영상에서의 모든 인식 오류 해결을 보장하지 않습니다.

## 0.7.9 후면 가로·세로 자세 보정 — 반영 1

기준 버전은 0.7.8 (`811b5ff5dca1557dfc93255e88dfecfd401af652`)입니다. 이번 변경은 손바닥이 보이는 동안 팔 길이 방향의 앞뒤 기울기를 보정합니다. 손가락이 사라진 뒤의 회전 예측은 추가하지 않았습니다.

- 처음 저장한 손바닥의 가로·세로 비율이 현재 관측과 달라지면 평면 맞춤이 실제보다 큰 길이 방향 기울기를 만들 수 있습니다. 후면에서는 세계 좌표와 정규화 깊이의 손목→손가락 뿌리 방향을 비교하고, 넓게 보이는 손바닥과 최근 여러 입력의 일관성을 확인한 뒤 이 기울기를 보정합니다. 두 출력은 같은 모델의 결과이며 독립된 센서나 실제 팔꿈치·전완 측정이 아닙니다.
- 보정 축은 화면 속 손 방향과 함께 돌아가므로 가로·세로에 같은 계산을 적용합니다. 보정량을 서서히 적용·해제하며 기존 손목 중심·크기와 손바닥 회전 후보 선택·초기 기준·6시/12시 기준은 유지합니다. 보정한 표시 자세를 회전 후보의 기억에 다시 넣지 않습니다. 후면 영상 보조에는 보정한 표시 자세를 전달해 연결 지점이 일치하도록 합니다.
- 전면에는 적용하지 않습니다. **관절·회전 진단 → 후면 팔 기울기 보정**을 끄면 같은 페이지에서 기존 자세와 비교할 수 있습니다. 카메라 전환·기준 재설정·화면 크기 및 착용 설정 변경은 보정 기억을 지웁니다. 관측 누락 시 확인 기록을 끊고 기존 220ms 표시 만료와 후면 영상 보조의 시간 제한을 유지합니다.

검증: 자동 검사 84개와 빌드 통과. 잘못 늘어난 기준 손바닥이 만드는 길이 방향 오차, 양손의 가로/세로/반대 방향, 화면 내 방향 유지, 실제 기울기 변화, 순간 깊이 오류, 전면 경로와 누락 만료를 검사했습니다. 최신 녹화의 로컬 재검출 입력에서 19.5–23.3초 구간은 두 버전 모두 39/39 프레임 표시를 유지했습니다. 표시 길이 축과 두 모델 출력 평균의 각도 차이는 평균 39.3→4.3도로 줄었습니다. 이는 **모델 출력과의 일치도이며 실제 손목 각도 오차가 아닙니다.** 프레임 사이 최대 회전 변화는 7.7→11.3도로 늘어 실제 기기에서 부드러움도 확인해야 합니다. 전면 재생 결과는 동일했습니다.

원본의 연결 직전 기준 자세는 녹화에 없고, 영상 재검출을 그대로 재생하면 초기 기준이 확정되지 않았습니다. 비교에서는 같은 영상의 한 관측으로 양쪽에 동일한 기준을 설정했습니다. 원본 시계·압축이 포함된 재검출이며 실제 휴대폰 추론·정확도 검증을 대신하지 않습니다. Android에서 손끝을 보인 채 가로→세로→가로로 옮기고, 세로 상태의 이동·작은 회전을 확인한 뒤 반영 2 진행 여부를 판단합니다. 개인 영상·좌표·재현 도구는 공개하지 않습니다.

## 0.7.8 초기 연결 거부 완화

0.7.7은 화면에 손이 충분히 보이는 경우에도 두 깊이 출력의 차이를 지나치게 엄격하게 거부했습니다. 새 후면 녹화의 로컬 재검출에서 유효 관측 304개 중 263개가 이 검사에 막혔습니다. 출력 간 차이는 주로 18–24도였는데 허용치는 약 16도였습니다. 두 출력의 차이를 곧바로 손 검출 실패로 취급해서는 안 됐습니다.

- 깊이 방향 차이 허용치를 약 34도로, 정면 조건을 약 35도 이내로 조정했습니다. 큰 깊이 불일치·축 반전·옆면은 계속 거부합니다.
- 고정된 구간 시작점 대비 회전 변화는 약 8→13도, 위치 변화는 손바닥 길이의 10→18%까지 허용합니다. 평균 기준이 계속 이동하는 방식으로 돌아가지 않았습니다. 크기·형태 안정 조건, 손끝 잘림·손가락 굽힘 검사와 최소 1.5초·12회 조건은 유지합니다.
- 기준 확정 뒤의 회전 필터·6시/12시 방향·손실 복구·후면 영상 보조는 변경하지 않았습니다.

검증: 75개 자동 검사와 빌드 통과. 적당한 깊이 편향과 작은 위치 움직임을 허용하면서 큰 기울기·불일치·축 반전은 거부하는 회귀 검사를 추가했습니다. 같은 녹화에서 재검출한 332개 입력을 순서대로 실행해 기존 버전의 첫 연결 실패를 재현했고, 수정 후 약 2.8초에 연결되어 289개 프레임에서 표시 가능한 자세를 반환했습니다. 실제 앱의 통제된 시각·카메라 입력 검사에서도 약 2.9초에 첫 표시를 확인했습니다. 프레임 반복이나 사전 기준 설정 없이 검사했습니다. 전면 반전 경로도 같은 좌표를 이용한 별도 통합 검사와 기존 회전 검사로 확인했습니다.

이 수치는 녹화 재검출·통제된 입력의 결과이며 실제 Android 카메라의 연결 시간이나 회전 정확도를 보장하지 않습니다. 개인 영상·관절 좌표·검사 도구는 공개하지 않습니다.

## 0.7.7 엄격한 초기 기준

- 첫 연결과 수동 기준 재설정에는 최소 1.5초·12회 연속 관측이 필요합니다. 손끝까지 화면 안에 있고 손가락을 편 상태, 손 평면의 정면 각도(약 21도 이내), 두 깊이 출력의 방향 일치(약 16도 이내)를 검사합니다. 실제 가림 여부를 판별하는 별도 모델은 없으며 좌표의 기하 조건을 확인합니다. 처음에는 손등을 보여 주세요. 손등·손바닥을 자동 분류하는 기능은 아닙니다.
- 회전, 위치, 크기, 손 형태의 변화는 구간 시작점과 비교합니다. 움직이는 평균을 따라가며 천천히 잘못된 기준을 배우지 않도록 했습니다. 누락·불량 입력은 누적을 취소하고, 오래 기다려도 조건을 자동으로 완화하지 않습니다. 낮은 처리 속도나 불안정한 입력에서는 2초보다 오래 걸릴 수 있습니다.
- 기다리는 이유와 진행률을 표시합니다. 확정 이후에는 이 초기 게이트를 다시 적용하지 않아 기존 손가락 굽힘·회전·짧은 누락 복구를 유지합니다. 전면의 역회전 복구와 6·12시 방향, 후면 영상 보조는 유지합니다.

검증: 72개 자동 검사와 정적 빌드 통과. 5/10/15/30fps 수준의 입력 간격, 중간 누락, 잘림·손가락 굽힘·깊이 불일치 거부, 느린 누적 이동 거부, 작은 떨림 허용, 기존 양손·카메라별 회전·재연결을 검사했습니다. 휴대폰 크기의 브라우저에서 통제된 입력으로 전면·후면과 수동 기준 재설정 모두 조건 미달 시 숨김→1.5초 안정 후 표시→누락 후 복구를 확인했습니다. 실제 카메라와 추론을 대체한 통합 검사이므로 실제 폰 정확도나 성능 측정은 아닙니다.

이전 개인 녹화를 재검출한 입력에는 움직임과 화면 잘림이 많아 새 기준의 연속 안정 조건을 충족하지 못했습니다. 새 버전에서는 사용자가 안내에 따라 처음 손을 멈추는 검증이 필요합니다. 두 깊이 출력도 같은 모델에서 나오므로 일치한다고 실제 각도가 보장되지는 않습니다.

## 0.7.6 전면 역회전 복구

- 초기 손 형태에 기울기 오차가 섞이면 화면에 맞는 두 깊이 후보가 정면에서도 합쳐지지 않을 수 있습니다. 기존의 이전 방향 우선·근거리 복구 조건은 이때 잘못된 후보를 계속 선택했습니다. 전면에서는 세계 좌표와 정규화 관절 깊이가 같은 후보를 뚜렷하게 지지하고, 관절 배치도 맞을 때 최소 3회·180ms 연속 확인 후 다시 선택합니다. 한 프레임 오류, 서로 다른 깊이 판단, 낮은 배치 일치도, 중간 누락은 확인을 취소합니다. 두 깊이 출력은 같은 모델의 결과이며 독립된 센서가 아닙니다.
- 큰 방향 차이는 확인 중 잠시 숨긴 뒤 다시 붙이고, 잘못된 회전 속도 기억을 지웁니다. 역방향 고착을 줄이는 대신 전환 시 짧은 끊김이 생길 수 있습니다. 선명한 손등·손바닥의 기존 복구, 6시→엄지/12시→새끼손가락 정렬과 착용 설정은 유지합니다. 이 추가 복구는 전면에만 적용하며 후면 영상 보조·카메라/워커·모델 설정은 수정하지 않았습니다.
- 진단에는 전면 깊이 확인 횟수·대기·복구 여부를 기록합니다. 화면에는 방향 재확인 상태를 표시합니다.

검증: 65개 자동 검사와 정적 빌드를 통과했습니다. 실제 각도를 아는 합성 입력에서 초기 기울기 편향, 양손 왕복 회전, 10/15/30fps 수준의 입력 간격, 한 프레임 오류, 깊이 출력 불일치, 관측 누락, 큰 방향 재부착을 검사했습니다. 기존 양손·카메라별 한 바퀴 회전과 6·12시 정렬 검사도 통과했습니다.

브라우저 앱에서도 통제된 좌표와 시각을 주입해 방향 재확인→숨김→재부착, 전면의 후면 보조 비활성화, 종료와 오류 없는 실행을 확인했습니다. 카메라와 추론을 대체한 통합 검사이며 실제 기기 성능 검사가 아닙니다. 이 환경의 실시간 재현 스트림은 약 1fps라 그대로는 기준 설정을 검증할 수 없었습니다.

새 개인 녹화에서 다시 검출한 동일 250프레임으로 0.7.4와 0.7.5의 자세 결과가 같았고, 두 버전 모두 반대 기울기 유지가 재현됐습니다. 이번 수정에서는 표시 자세가 뚜렷한 모델 깊이 방향과 반대인 프레임이 60→2로 줄었고, 표시 프레임은 231→218로 줄었습니다. **모델 깊이를 기준으로 한 진단 지표이며 실제 각도 정확도 측정은 아닙니다.** 녹화 시작 전의 원래 기준 자세를 알 수 없고 기존 AR·압축이 포함되어 있어 실제 폰 동작을 완전히 재현하지 못합니다. 이전 후면 240프레임의 위치·회전·크기·표시 여부는 동일했습니다. 이전 전면 두 자료는 재확인 중 일부 숨김으로 표시 수가 127/140→125/140, 183/191→180/191로 변했습니다. 지속적인 모델 오인식, 손가락 가림과 강한 원근에서는 오류가 남을 수 있습니다. 개인 영상·관절·재현 도구는 공개하지 않습니다.

## 0.7.5 후면 근접·움직임 보조 (시험 적용)

- 후면에만 영상 특징을 따라가는 보조 경로를 추가했습니다. 기존 손 추적이 정상인 동안 손목 중심의 투영된 타원 영역에서 특징을 잡고, 손 관절이 끊기거나 자세가 거부되면 카메라 영상의 이동·확대·화면 내 회전으로 잠시 이어갑니다. 렌더링된 시계 화면을 추적하지 않습니다.
- 기본으로 켜진 **후면 근접·움직임 보조** 체크박스로 비교할 수 있습니다. 끄면 기존 후면 경로로 돌아가며 손등 기준을 다시 잡습니다. 전면에서는 영상 추출·보조 추적·추가 자세 거부를 실행하지 않습니다. 기존 관절 자세 계산, 6·12시 정렬, 모델과 착용 설정은 유지합니다.
- 추적할 특징이 8개 이상이고, 왕복 추적·위치 오차·분포·이동 모델의 일치 검사를 통과해야 이어갑니다. 마지막으로 신뢰한 손 관절 입력에서 **최대 1초**, 새 영상 근거는 140ms 안에 있어야 합니다. 잘못된 흐름, 지나친 누적 확대·회전, 화면 크기 변경, 카메라 전환·종료, 설정 변경은 보조 기억을 끊습니다. 보조 추적만으로 시간 제한을 갱신하거나 사라진 특징을 배경에서 새로 잡지 않습니다.
- 보조 구간은 마지막 앞뒤 기울기를 유지하면서 2D 위치·크기·화면 내 방향만 갱신합니다. 새로운 3D 손목 회전이나 원근 자세를 복원하는 기능이 아닙니다. 다시 손을 찾으면 최대 180ms에 걸쳐 기존 추적으로 돌아갑니다. 피부 무늬 부족, 흐림, 가림, 조명 변화와 팔 움직임/배경 혼동으로 일찍 종료되거나 미끄러질 수 있습니다.
- 아래로 크게 꺾여 손목-손가락 뿌리 간격이 지나치게 눌린 관절 배치, 잘린 손바닥, 기준 형태에 맞지 않는 배치, 독립된 영상 이동과 크게 어긋나는 위치는 후면에서 거부합니다. 잘못된 자세가 고착되는 일을 줄이기 위한 보수적인 처리이며, 손과 팔의 꺾임을 분리하거나 완전한 원근 카메라 모델을 적용한 것은 아닙니다. 극단적인 자세에서는 시계가 더 빨리 숨겨질 수도 있습니다.
- 후면 보조를 켜면 기존 전면용의 제한된 재연결 조건도 후면에 적용합니다. 같은 좌우 분류·비슷한 크기의 손 하나가 제한된 새 위치에서 4회·350ms 유지되어야 하며, 작은 배경 손·다른 쪽 손·겹치는 손으로 자동 전환하지 않습니다.
- [Lucas–Kanade 광학 흐름의 원리](https://docs.opencv.org/4.13.0/db/d7f/tutorial_js_lucas_kanade.html)를 사용하는 독립 구현입니다. 새로운 외부 SDK나 모델은 추가하지 않았습니다. 후면 입력의 긴 변을 최대 480px로 줄여 처리하며, 영상은 메모리에서만 사용하고 진단 파일에도 픽셀은 넣지 않습니다. 기기별 추가 처리 비용은 실제 폰에서 확인해야 합니다.

검증: 60개 자동 검사와 빌드를 통과했습니다. 이동·확대·화면 회전, 무늬 없는 입력/장면 변경 거부, 특징 분포와 이상값, 1초 만료, 손 복귀, 세로 화면 좌표, 극단적인 기울기 거부를 확인했습니다. 실제 손 사진에 통제된 2D 이동·확대를 적용하고 관절 입력을 끊은 검사에서 30프레임(0.99초)을 이어갔습니다. 실제 손목의 3D 회전·변형을 재현한 검사가 아닙니다.

이전 개인 녹화의 같은 좌표와 영상을 재생했을 때 후면 표시 프레임 수는 157/240으로 기존과 같았습니다. 전면 140프레임의 위치·회전·크기 계산은 기존과 동일했습니다. 기존 AR이 합성된 녹화이므로 광학 흐름의 실제 피부 추적 정확도를 측정할 수 없으며, 실사용 개선을 입증한 수치가 아닙니다. 브라우저에서 worker/호환 경로의 모델 추론, 후면 영상 전달, 전면 비활성화, 전환·종료와 UI를 확인했습니다. 로컬 재현 스트림은 이 환경에서 약 1fps로 동작해 앱 전체의 실시간 착용은 검증하지 못했습니다. 실제 Android 카메라에서 추가 검증이 필요합니다. 개인 영상·좌표·검사 도구는 공개하지 않습니다.

## 0.7.4 손등·손바닥 기준 복구와 방향 확인

- 회전 복구에 손바닥 쪽의 선명한 관측도 사용합니다. 화면 관절 배치와 추정 3D 방향이 모두 넓은 손 표면을 가리키고, 같은 면·비슷한 방향이 최소 4회·300ms 유지되어야 새로운 기준으로 인정합니다. 옆면, 불일치한 깊이, 번갈아 바뀌는 판단, 중간 누락은 확인을 취소합니다. 기존 손등 복구 경로도 유지합니다.
- 선명한 표면에서 지속적으로 다른 회전 해가 확인되면 잘못 유지하던 깊이 방향을 다시 선택할 수 있습니다. 연속 추적 중에는 기존 회전 속도 제한을 적용합니다. 손바닥이 카메라를 향하면 시계 본체는 손목 뒤에 남아 가려지고, 스트랩이 앞에 보이는 것이 정상입니다. 카메라에 보이는 면으로 본체를 옮기는 기능이 아닙니다.
- 초기 추정 3D 좌표축과 화면 관절 순서가 반대일 때, 기존 부호만으로 6시 방향을 정하면 엄지 반대쪽을 가리킬 수 있는 경우를 합성 관절로 재현했습니다. 이제 보정된 기준 손 형태의 실제 엄지 축 순서까지 반영합니다.
- 임시 시계에 12·6 숫자를 표시하고, **6·12시 방향 다시 맞추기** 버튼을 추가했습니다. 이 버튼은 방향 90°·기울기 0°를 저장하고, 카메라 사용 중에는 손등 기준을 다시 잡습니다. 크기·착용 위치·손목 너비·두께는 유지합니다. GLB는 +Y가 12시인 모델 규격을 따릅니다.
- 화면 상단에 버전을 표시하고, 진단 JSON에 표면 추정·표면 확인 여부·시계의 엄지 축 부호를 기록합니다. 처음 기준을 잡을 때는 여전히 손등을 보여야 합니다. 피부나 손금을 인식하는 별도의 표면 분류 모델은 추가하지 않았습니다. [MediaPipe의 기본 출력](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker)은 관절 좌표와 좌우 손 분류이며, 이 기능은 그 관절과 기존 손등 기준을 이용한 기하학적 추정입니다.

50개 자동 검사를 통과했습니다. 양손·미러링에서 긴 누락 후 손바닥으로 복구, 손목 뒤 본체 위치 유지, 흔들리는 표면 판단 거부, 잘못 유지된 회전의 속도 제한 보정, 초기 3D 축 반전 시 6·12시 정렬을 추가 확인했습니다. 새로운 녹화의 동일 관절 입력에서 표시 프레임 수는 기존과 같았고, 일부 안정된 손등 구간에서 새 회전 기준이 확인됐습니다. 지속적인 전면 역방향은 방향 90°의 로컬 재현에서 동일하게 나타나지 않았으므로 해당 녹화의 원인을 확정하거나 실제 폰의 회전 정확도가 개선됐다고 단정하지 않습니다. 손가락 가림·손목 꺾임의 한계는 남습니다. 개인 영상·좌표·재현 도구는 공개하지 않습니다.

## 0.7.3 전면 카메라 방향·대상 복구

- 손등 기준 설정에서 고정한 엄지 축을 시계 방향에도 반영합니다. 기본 방향 90°에서 **6시는 엄지, 12시는 새끼손가락 쪽**입니다. 양손과 전·후면 반전을 처리하며, 모델 방향에 더한 수동 조절 값은 유지합니다. 이전에 방향을 임의로 바꿨다면 시계 방향만 90°로 되돌려 확인하세요.
- 전면 카메라에서만, 추적 대상이 기존 화면 위치를 크게 벗어나 연결이 끊겼을 때 제한된 재연결을 허용합니다. 같은 좌우 분류·비슷한 크기의 손 하나가 제한된 거리 안에서 최소 4회·350ms 안정적으로 보여야 합니다. 다른 손, 작은 배경 손, 여러 손이 겹친 경우에는 자동 전환하지 않습니다. 사람의 신원을 구별하는 기능은 아닙니다.
- 재연결 뒤에도 기존 회전 기억과 손등 방향 확인을 통과해야 시계를 표시합니다. 후면 카메라의 대상 선택 조건과 회전 필터는 바꾸지 않았습니다. 진단 기록에는 기준 축의 부호와 적용된 시계 방향도 저장합니다.

45개 자동 검사를 통과했습니다. 개인 화면 녹화에서 재검출한 동일한 191프레임 입력을 비교해 대상 선택은 30→181프레임, 시계 표시는 32→183프레임이었습니다. 첫 프레임 반복으로 기준을 설정한 뒤 비교했으며, 녹화의 거울 반전을 되돌렸습니다. 화면 일부만 재검출했고 기존 AR과 녹화 압축이 포함되어 있으므로 실제 폰의 검출률·각도 정확도 측정은 아닙니다. 개인 영상·좌표·재현 도구는 공개하지 않습니다.

## 0.7.2 실험 모드 철회

- Android 실사용에서 시계가 표시되지 않는 문제가 이어져 손목 직접 추적 실험 모드를 철회했습니다. 현재 앱은 기존 MediaPipe 손 관절 추적만 사용합니다. 모드 선택 UI와 실행 경로를 제거했으며 해당 SDK·모델을 더 이상 다운로드하거나 배포하지 않습니다. 이전 실험 소스는 이력 참고용이며 앱에서 불러오지 않습니다.
- 0.7.1의 개선된 스트랩, 기존 추적·회전 보정, 시계·손목 기본 크기와 기존 손 관절 모드의 저장 설정은 유지합니다. 이 릴리스는 손등에서의 한쪽 기울기·중심 오차를 수정한 버전이 아닙니다.
- 현재 손등 기준 설정은 카메라 정면을 강제하는 영점 보정이 아닙니다. 추정된 초기 3D 기울기를 기준 형태에 반영하며, 팔의 실제 방향을 직접 관측하지 않습니다. 정면 기준 보정과 팔 축 추정 분리는 후속 검토 대상입니다.
- 기존 추적·스트랩과 설정 저장의 41개 자동 검사, 빌드, 로컬 브라우저의 손 추적 시작·시계 표시·기준 재설정·카메라 종료를 확인했습니다. 철회한 모드의 검사 6개는 활성 검사 대상에서 제외했습니다.

아래 0.7과 0.7.1의 실험 모드 설명은 과거 변경 기록입니다. 현재 사용 가능한 기능이 아닙니다.

## 0.7.1 스트랩 곡면과 실험 모드 자세 계산 수정

- 임시 시계의 스트랩을 본체 연결점에서 손목 타원에 접하는 경로로 연결합니다. 기존의 긴 곡선 혼합 구간이 손목 위에 평평하게 뜨는 형상을 줄입니다. 이후 구간은 동일한 손목 원기둥을 감싸며 뒤쪽은 깊이 가림을 적용합니다.
- 기존 손 관절 추적 계산, 보정과 기본 크기, 저장된 착용 값은 변경하지 않았습니다. 손목 모형이 실제 팔보다 크거나 축이 어긋나면 스트랩이 뜨는 문제는 별도로 남을 수 있습니다. 본체보다 손목이 넓으면 위에서 보이는 스트랩이 완전히 사라지지는 않습니다. GLB 메시 자동 변형은 포함하지 않습니다.
- 47개 자동 검사와 동일한 손목 크기·자세의 위/사선/옆 렌더링 비교로 연결점, 표면 접촉과 가림을 확인했습니다. 실제 Android에서의 외관 개선은 재확인이 필요합니다.
- 실험 모드에서 카메라 방향을 강제하던 PnP 옵션을 제거하고, 현재 기준점과 자세의 재투영 오차를 직접 계산합니다. SDK의 방향 제약 경로는 해가 없을 때 이전 오차를 재사용할 수 있어 현재 프레임의 검사값으로 신뢰하지 않습니다. 검출·자세 탈락·재확인·표시를 진단 화면에서 구분합니다.
- 개인 녹화의 로컬 재생에서 검출 후 자세 탈락을 재현하고, 수정 후 시계 표시를 확인했습니다. 기존 AR이 포함된 화면 녹화이므로 실제 Android 카메라에서 같은 문제가 해결됐다는 보장은 아닙니다. 손목 전용 모드는 계속 실험 옵션으로 유지합니다.

## 0.7 손목 직접 추적 비교와 착용 설정 저장

- **추적 방식 → 손목 직접 추적 · 실험**에서 WebAR.rocks의 손목 주변 8개 기준점 모델을 시험할 수 있습니다. 기본 모드는 기존 MediaPipe입니다. 전환 시 카메라와 추적기를 종료·재시작하며 두 모델을 동시에 실행하지 않습니다.
- 새 모드는 손등 쪽 손목의 위치·폭·방향을 모델의 기준 형상과 맞춥니다. 손바닥 평면에서 팔 방향을 연장하지 않습니다. 자동 피부 윤곽 분할이나 실제 mm 측정 기능은 아닙니다. 손목이 화면에 충분히 보여야 하고 옆면·손바닥에서는 인식이 끊길 수 있습니다.
- 손목 직접 추적은 위치와 회전의 유효 시간을 따로 관리합니다. 불확실한 회전을 잠깐 유지하는 동안 새로 측정한 위치를 따라가며, 반복되는 큰 방향 변화는 확인 후 속도를 제한해 반영합니다. 영상 광학 흐름으로 누락을 연결하는 기능은 아직 포함하지 않습니다.
- 기존 모드 기본값을 시계 135%, 손목 너비 130%, 두께 140%로 확대하고 조정 상한을 200%로 넓혔습니다. 직접 추적 모드는 기준 손목 폭을 쓰므로 별도의 기본값을 사용합니다.
- 조절 값과 가림 설정은 추적 방식·모델별로 저장합니다. 모델을 다시 불러오거나 임시 시계로 돌아와도 저장된 프로필을 불러옵니다. 초기화는 현재 프로필을 기본값으로 저장합니다. 브라우저의 저장 차단 시에도 앱은 계속 사용할 수 있습니다.
- 진단 JSON에 활성 추적 방식과 손목 기준점·투영 결과를 기록합니다. 원본 영상은 포함하지 않습니다. 검출 점수와 투영 일치도는 실제 정확도 수치가 아닙니다.

45개 자동 검사와 로컬 브라우저에서 두 추적기 준비·전환·재시작·카메라 종료, 프로필 저장·새로고침·초기화, 녹화 입력의 실제 손목 검출과 시계 배치를 확인했습니다. 녹화에 기존 AR 시계가 포함되고 카메라 원본 일부가 잘려 있으므로 정확도 비교 수치로 사용하지 않습니다.

이 모드는 같은 휴대폰과 동작으로 비교하기 위한 실험 기능입니다. 특정 녹화에서 관절 추적보다 정확하다는 주장은 하지 않습니다.

## 0.6 손목 곡면에 맞추는 스트랩과 순간 튐 완화

- 손목 중심에 **타원형 원기둥 하나**를 두고 시계 본체의 접촉 위치, 임시 시계 스트랩의 곡선, 손목 뒤 가림에 같은 치수를 사용합니다. 본체는 원기둥 표면에 놓이고 스트랩은 옆면과 뒷면을 돌아 본체 연결점으로 이어집니다.
- 시계 크기를 바꿔도 추정 손목 둘레는 유지합니다. 스트랩의 폭은 시계 크기를 따르고, 감싸는 곡선은 손목 크기를 따릅니다.
- **손목에 감기도록 맞추기 → 손목 모형 보기**를 켜고 손등에서 **손목 너비**, 옆면에서 **손목 두께**를 조정합니다. 조절 값은 추정치에 대한 비율이며 mm나 실제 둘레 측정값이 아닙니다. 피부 윤곽을 직접 검출하지 않고 손 관절과 초기 손바닥 기준으로 크기·축을 추정합니다.
- 불확실한 회전 프레임에서 기존 회전에 새로운 원시 위치·크기를 섞던 처리를 없앴습니다. 마지막 유효한 자세 전체를 잠깐 유지하고, 갑작스러운 위치·반경 변화는 이어지는 관측으로 확인합니다.
- 회전 보간에는 이미 관측한 움직임을 기준으로 한 변화 속도 제한을 적용합니다. 한 프레임의 잘못된 각도가 스스로 보정 속도를 높여 크게 튀는 것을 줄입니다. 빠른 실제 움직임에는 반응 지연이 추가될 수 있으며, 가림·모호한 자세에서는 기존의 숨김과 방향 복구 안내를 유지합니다.
- 자동으로 감기는 스트랩은 **임시 시계에 적용**됩니다. 가져온 GLB는 손목 모형으로 정렬·가림을 처리하지만 메시 형태를 자동 변형하지 않습니다. 자체 모델에 같은 변형을 적용하려면 본체와 스트랩을 분리하고 연결점 또는 스킨·모프 규격을 함께 정해야 합니다.

39개 자동 검사, 로컬 브라우저의 모형 표시·너비/두께 조절·초기화·GLB 교체·카메라 종료, 개인 녹화 255프레임의 재추론 비교를 검증했습니다. 화면 녹화 재추론에는 기존 AR 시계가 포함되므로 실제 각도의 정확도 평가와 같지 않습니다. 개선 정도와 지연은 Android 기기에서 다시 확인해야 합니다. 검증 영상·좌표·테스트 GLB는 공개 저장소에 포함하지 않습니다.

## 0.5 추적 대상 유지와 회전 복구

- 최대 두 손의 검출 결과를 비교하여 처음 안정적으로 보인 큰 손을 선택합니다. 손목 위치·손 크기·좌우 손 분류로 같은 대상을 이어가며, 검출 순서가 바뀌거나 기존 손이 사라져도 작은 배경 손에 바로 붙이지 않습니다. 겹친 두 손을 구별하기 어려우면 추적을 보류합니다. 사람의 신원을 식별하는 기능은 아닙니다.
- 시계 표시의 220ms 만료와 회전 기억을 분리했습니다. 이전 회전은 최대 1.5초까지 복구에 사용하며, 최근 각속도는 다음 회전 후보 선택에만 짧게 반영합니다. 보이지 않는 손의 움직임을 계속 그리지는 않습니다.
- 짧은 누락 후에는 같은 회전이 최소 3회·60ms 확인되어야 표시를 재개합니다. 1.5초 이상 회전을 확인하지 못하면 손등을 다시 카메라 쪽으로 펴고 잠깐 유지해야 방향이 복구됩니다. 옆면에서 잘못된 앞뒤 방향을 선택해 계속 도는 일을 줄이기 위한 보수적인 처리입니다.
- 손바닥을 보였다가 실제로 되돌리는 동작은 여러 프레임의 3D 방향 증거로 확인합니다. 회전 예측만으로 한 방향 회전을 강제하지 않습니다.
- 추적 대상이 복구되지 않으면 같은 손을 원래 위치로 가져오거나 **손등 기준 맞추기**를 누르세요. 이 버튼은 추적할 손과 회전 기준을 함께 다시 선택합니다. 다른 손으로 바꿀 때도 사용합니다.
- 진단 JSON에 선택한 손의 인덱스·검출 수·대상 상태·회전 기억의 경과 시간을 추가했습니다. 최대 두 손 추론에 따른 기기별 처리 시간 변화는 휴대폰에서 확인해야 합니다.

33개 자동 검사에는 검출 순서 변경, 배경 손 거부, 좌우 손 변경, 손 겹침, 누락 후 잘못된 깊이값, 긴 가림 후 복구, 실제 회전 반전이 포함됩니다. 개인 화면 녹화의 로컬 재추론에서도 끝부분의 배경 손 검출 3회를 거부하고 시계를 숨기는 것을 확인했습니다. 실제 Android의 원본 입력에 대한 정확도 보장은 아닙니다.

## 0.4 화면 관절 배치로 회전 보정

- 손등 기준 설정 때 최소 0.5초·6회 이상의 일관된 관측으로 손바닥 평면의 기준 형태를 만듭니다. 모델의 프레임별 뼈 길이 대신 화면에서 관측한 기준 형태를 사용합니다.
- 매 프레임 손목·네 손가락 뿌리를 기준 형태에 맞추어 투영 변화를 계산합니다. 화면상 손 폭과 관절 배치로 기울기 크기를 구하고, 추정 3D 깊이와 이전 방향으로 앞뒤 깊이의 모호성을 풉니다. 각도 상한은 없으며 양방향 전체 회전을 허용합니다.
- 배치 오차가 크면 회전을 잠깐 유지하고, 220ms 이상 확신할 수 없으면 시계를 숨깁니다. 진단의 ‘배치 일치도’는 이 기하학적 일관성을 뜻하며 실제 정확도 점수가 아닙니다.
- 기준 손 폭과 투영 배율로 시계 크기·손목 반경을 계산하여 모델의 추정 뼈 길이 변화가 크기에 바로 반영되는 것을 줄입니다.
- 회전의 중복 보간을 없애고 추론 요청 시각을 기준으로 결과의 나이를 판단합니다. 표시되는 회/초는 추론 실행 횟수입니다.
- **관절·회전 진단 → 관절·회전 표시**로 진단 선을 켭니다. **진단 기록 시작 → 진단 기록 저장**으로 좌표·설정·표시 회전·처리 시간을 JSON으로 기기에 저장합니다. 0.7.11부터 기록 상태와 시계 표시 표본 수를 화면에서 확인할 수 있습니다. 영상이나 모델은 포함하지 않으며 자동 업로드하지 않습니다.

손목 윤곽이나 팔을 직접 인식하는 기능은 아직 없습니다. 약한 원근 투영의 평면 근사이므로 손목 꺾임, 손가락 가림, 큰 원근 왜곡에서 오차가 남을 수 있습니다. 화면 녹화 재분석은 이미 AR이 합성되고 화면이 잘린 영상을 다시 추론하는 것이므로 폰의 원본 추적 결과나 실제 각도 정답과 같지 않습니다.

## 0.3에서 유지한 회전 처리

- 엄지의 CMC·MCP 관절(1·2)과 새끼손가락 MCP(17)의 3D 위치 차이를 검지·중지·약지 뿌리 및 손목과 함께 사용합니다. 손가락 끝을 벌리는 동작은 회전 계산에 넣지 않습니다.
- 손등 기준을 처음 한 번 정하고 추적 누락 후에도 유지합니다. 0.2의 약 49~54도 기울기 제한과 옆면에서의 각도 고정을 제거했습니다. 손등 → 옆면 → 손바닥 방향으로 연속 회전할 수 있습니다.
- 첫 인식은 손등을 보여 주는 사용 조건에 의존합니다. 손바닥으로 시작하거나 다른 손으로 바꾸면 **손등 기준 맞추기**가 필요할 수 있습니다. 자동 손바닥/손등 분류 기능은 아닙니다.
- 시계가 손목 중심을 축으로 돌도록 수정했습니다. 손바닥이 보이는 자세에서는 시계 본체가 손목 뒤에 가려질 수 있습니다. 시계 크기를 바꿔도 추정 손목 반경은 유지합니다.
- 회전 전체를 제한하는 대신 한 프레임만 발생하는 큰 각도 이상값을 걸러내고 quaternion으로 보간합니다.

## 0.2에서 유지한 안정화

- 손목과 네 손가락의 시작 관절을 함께 사용합니다.
- 움직이는 속도에 따라 위치 보정 강도를 조절하고 크기 변화와 순간적인 위치 튐을 완화합니다.
- 짧은 누락은 최대 220ms 유지하고, 그 뒤에도 손을 찾지 못하면 시계를 숨깁니다.
- 가능한 브라우저에서는 Web Worker에서 추적합니다. 처리 중인 프레임을 쌓지 않으며 입력의 긴 변은 최대 640픽셀로 줄입니다. Worker를 사용할 수 없으면 기존 스레드에서 동작합니다.
- 기기 성능에 따라 최대 30회/초를 목표로 추적합니다. 실제 속도는 화면에 표시되며 기기마다 다릅니다.

## 모델 준비

- glTF 2.0 `.glb`로 내보내며 텍스처와 데이터를 파일 안에 포함합니다.
- 초기 권장 목표는 5~10MB 이하, 텍스처 1K~2K입니다. 파일 선택 상한은 40MB입니다.
- 본체·유리·스트랩을 분리해 두면 후속 조정에 편리합니다.
- 케이스 지름·두께·스트랩 폭을 mm로 함께 준비합니다. 현재 크기 조절은 실제 치수 측정 기능이 아닙니다.
- 좌표 기준: X는 케이스 좌우, Y는 다이얼 12시·6시와 스트랩 방향, +Z는 다이얼 앞면입니다. 피부 접촉면을 Z=0으로 두면 맞추기 쉽습니다.
- 일반 GLB는 X축 전체 너비로 정규화하고 X/Y 중심을 맞추며 Z 원점을 유지합니다. 착용 메타데이터가 있는 준비된 모델은 케이스 지름과 뒷면 접촉점을 기준으로 정렬합니다.
- 스트랩은 손목을 감싸는 착용 형태로 모델링합니다. 펼쳐진 스트랩을 자동으로 구부리지는 않습니다.
- 기본 시계 회전은 90°입니다. 모델에 따라 방향·높이 설정을 조절합니다.
- Draco 압축은 지원합니다. KTX2/BasisU와 Meshopt 압축은 끄고 내보내 주세요.

## 로컬 개발

Node.js 20 이상이 필요합니다.

```sh
npm ci
npm start
```

PC에서 http://localhost:4173 을 엽니다. `npm start`가 버전이 고정된 라이브러리와 공식 추적 모델을 `vendor/`에 준비합니다. 모델 파일은 SHA-256 해시를 검사합니다.

```sh
npm test
npm run build
```

`dist/`가 HTTPS 호스팅용 결과물입니다. GitHub Actions가 main 브랜치에 변경 사항이 반영될 때 테스트·빌드 후 GitHub Pages로 배포합니다. Pages 설정의 배포 Source는 **GitHub Actions**입니다.

휴대폰에서 로컬 개발 서버를 보려면 USB 포트 전달을 사용합니다. ADB가 설치된 PC에서는 `adb reverse tcp:4173 tcp:4173` 실행 후 휴대폰 Chrome에서 http://localhost:4173 을 엽니다. 같은 Wi-Fi의 일반 HTTP IP 주소는 카메라 보안 조건을 만족하지 않습니다.

## 현재 한계와 검증

단일 RGB 카메라의 손 관절을 사용한 시각적 추정입니다. 손목 둘레나 실제 시계 크기를 측정하지 않습니다. 손등이 보이는 자세에 맞춘 초기 버전이며 손바닥/손등을 자동 분류하지 않습니다. 큰 회전, 빠른 움직임, 손가락 가림에서 어긋날 수 있습니다.

가림 처리는 보이지 않는 타원형 손목 모형을 사용합니다. 정밀한 피부 분할, 소매나 다른 물체에 의한 가림, 접촉 그림자, 환경 반사, 스트랩 자동 변형은 구현하지 않았습니다. 팔 자체의 방향은 추적하지 않으므로 손목을 크게 꺾으면 손 방향과 팔 방향이 달라져 어긋날 수 있습니다.

단위 검사와 데스크톱 Chromium에서 모바일 화면, GLB 교체, 권한 거부 후 복구, 실제 MediaPipe 모델에 테스트 손 영상을 입력하는 추적, 손이 사라질 때 숨김, 카메라 스트림 종료를 확인했습니다. 실제 Android 기기에서의 추적 정확도와 속도는 별도 검증이 필요합니다.

0.2에서는 깊이 이상값, 옆면 자세, 누락·재검출, 위치 튐, 정지 흔들림과 이동 지연의 회귀 검사를 추가했습니다. 화면 녹화를 로컬에서 재분석해 이전 자세 계산과 비교했습니다. 화면 녹화에는 기존 AR 오버레이가 포함되어 있으므로 원본 카메라 영상이나 실제 위치 정답에 대한 정확도 평가와는 다릅니다. 검증용 개인 영상은 저장소와 배포에 포함하지 않습니다.

0.3 회귀 검사는 합성 3D 관절의 양쪽 90도·전체 회전, 좌우 손, 전면 미러링, 손가락 끝만 움직이는 경우, 순간적인 180도 이상값, 재검출 때 기준 방향 유지, 손목 회전 중심 유지 등을 포함합니다. 0.4는 여러 축의 투영 복원, 틀린 3D 깊이에 대한 보정, 좌우 손·미러링에서 양방향 전체 회전, 관절 배치 불일치 시 만료·복귀, 뼈 길이 변화와 크기·확대 구분, 오래된 결과 거부, 시간 기반 기준 설정을 추가했습니다. 이 검사는 계산의 방향·연속성을 검증하며 실제 카메라의 관절 추정 정확도를 보장하지 않습니다. 손 관절의 깊이 추정 오류나 손목과 팔 사이의 꺾임은 여전히 오차 원인입니다.

## 구현과 출처

[VeinSyct/Wrist-AR](https://github.com/VeinSyct/Wrist-AR)의 카메라 → 손 추적 → 시계 정렬 흐름을 참고한 **독립 구현**입니다. 원본 저장소를 수정한 포크는 아닙니다.

원본 검토 커밋은 `b21e71ae69edeafab22da277b27f4b8282254bb2`입니다. 원본의 public 코드는 MediaPipe를 사용하지만, dist의 SDK 메타데이터는 DeepAR 5.6.19를 선언합니다. 이 프로젝트에는 참고 저장소의 SDK·키·인코딩된 코드·시계 모델을 포함하지 않습니다. 별도로 사용자가 제공한 Datejust GLB를 개발 검증용으로 포함하며, 원본의 메시·텍스처를 유지한 채 유리 재질과 착용 기준점만 조정했습니다.

- Three.js 0.180.0 (MIT)
- MediaPipe Tasks Vision 0.10.32 (Apache-2.0)
- 공식 Hand Landmarker float16 모델, 버전 1
- 직접 작성한 임시 시계 모델

관련 고지는 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)를 확인하세요.

## 주요 파일

- `app.js`: 카메라, 렌더링, GLB 불러오기, UI
- `pose.js`: 화면 좌표와 손목 위치·방향 추정
- `palm-projection.js`: 손의 기준 형태와 화면 투영 맞춤
- `hand-target.js`: 검출 순서와 무관한 추적 대상 유지
- `hand-detector.js`, `hand-worker.js`: 비동기 손 추적과 호환 모드
- `watch.js`: 임시 시계 본체와 GLB 검사
- `wrist-rig.js`: 타원형 손목 모형, 맞춤 스트랩, 본체 접촉 위치와 가림
- `index.html`, `style.css`: 모바일 화면
- `prepare-assets.mjs`, `build.mjs`: 실행 파일 준비·빌드
- `core.test.mjs`: 좌표 변환과 GLB 검사
