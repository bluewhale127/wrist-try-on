# 손목 위의 시계

Android Chrome에서 손목을 비추고 3D 시계를 착용해 보는 웹 프로토타입입니다.

**실행 주소:** https://bluewhale127.github.io/wrist-try-on/

## 휴대폰에서 사용하기

1. Android Chrome에서 위 주소를 엽니다.
2. **카메라 시작**을 누르고 카메라 권한을 허용합니다.
3. 밝은 곳에서 **손등과 편 손가락이 카메라를 향하도록 1초 정도 유지**해 주세요. 방향이 반대로 붙으면 손등을 보인 상태에서 **손등 기준 맞추기**를 누릅니다. 다른 손으로 바꿀 때도 기준을 다시 맞춥니다.
4. 시계 크기, 착용 위치, 방향을 맞춥니다.
5. 준비한 시계가 있으면 **내 시계 불러오기**에서 `.glb`를 선택합니다.

카메라 영상과 선택한 시계 파일은 기기 안에서 처리하며 서버로 업로드하지 않습니다. 첫 페이지 접속 때 추적 모델 등 실행 파일을 다운로드합니다. 카메라를 끄거나 다른 탭/앱으로 이동하면 스트림을 종료합니다. 모델과 조절 값은 새로고침하면 초기화됩니다.

## 기능

- 후면 카메라를 기본으로 사용하는 손목 위치·방향 추적
- 직접 만든 임시 시계와 GLB 모델 교체
- 크기, 손목 위 위치, 시계 회전, 모델 기울기·높이 조정
- 손목 뒤 스트랩을 가리는 근사 처리
- 카메라 권한 오류 안내와 추적 손실 시 시계 숨김

## 0.6 손목 곡면에 맞추는 스트랩과 순간 튐 완화

- 손목 중심에 **타원형 원기둥 하나**를 두고 시계 본체의 접촉 위치, 임시 시계 스트랩의 곡선, 손목 뒤 가림에 같은 치수를 사용합니다. 본체는 원기둥 표면에 놓이고 스트랩은 옆면과 뒷면을 돌아 본체 연결점으로 이어집니다.
- 시계 크기를 바꿔도 추정 손목 둘레는 유지합니다. 스트랩의 폭은 시계 크기를 따르고, 감싸는 곡선은 손목 크기를 따릅니다.
- **손목에 감기도록 맞추기 → 손목 모형 보기**를 켜고 손등에서 **손목 너비**, 옆면에서 **손목 두께**를 조정합니다. 조절 값은 추정치에 대한 비율이며 mm나 실제 둘레 측정값이 아닙니다. 피부 윤곽을 직접 검출하지 않고 손 관절과 초기 손바닥 기준으로 크기·축을 추정합니다.
- 불확실한 회전 프레임에서 기존 회전에 새로운 원시 위치·크기를 섞던 처리를 없앴습니다. 마지막 유효한 자세 전체를 잠깐 유지하고, 갑작스러운 위치·반경 변화는 이어지는 관측으로 확인합니다.
- 회전 보간에는 이미 관측한 움직임을 기준으로 한 변화 속도 제한을 적용합니다. 한 프레임의 잘못된 각도가 스스로 보정 속도를 높여 크게 튀는 것을 줄입니다. 빠른 실제 움직임에는 반응 지연이 추가될 수 있으며, 가림·모호한 자세에서는 기존의 숨김과 방향 복구 안내를 유지합니다.
- 자동으로 감기는 스트랩은 **임시 시계에 적용**됩니다. 가져온 GLB는 손목 모형으로 정렬·가림을 처리하지만 메시 형태를 자동 변형하지 않습니다. 자체 모델에 같은 변형을 적용하려면 본체와 스트랩을 분리하고 연결점 또는 스킨·모프 규격을 함께 정해야 합니다.

39개 자동 검사, 로컬 브라우저의 모형 표시·너비/두께 조절·초기화·GLB 교체·카메라 종료, 개인 녹화 255프레임의 재추론 비교를 검증했습니다. 화면 녹화 재추론에는 기존 AR 시계가 포함되므로 실제 각도의 정확도 평가와 같지 않습니다. 개선 정도와 지연은 Android 기기에서 다시 확인해야 합니다. 검증 영상·좌표·테스트 GLB는 공개 저장소에 포함하지 않습니다.

## 0.5 추적 대상 유지와 회전 복구

- 최대 두 손의 검출 결과를 비교하여 처음 안정적으로 보인 큰 손을 선택합니다. 손목 위치·손 크기·좌우 손 분류로 같은 대상을 이어가며, 검출 순서가 바뀌거나 기존 손이 사라져도 작은 배경 손에 바로 붙이지 않습니다. 겹친 두 손을 구별하기 어려우면 추적을 보류합니다. 사람의 신원을 식별하는 기능은 아닙니다.
- 시계 표시의 220ms 만료와 회전 기억을 분리했습니다. 이전 회전은 최대 1.5초까지 복구에 사용하며, 최근 각속도는 다음 회전 후보 선택에만 짧게 반영합니다. 보이지 않는 손의 움직임을 계속 그리지는 않습니다.
- 짧은 누락 후에는 같은 회전이 최소 3회·60ms 확인되어야 표시를 재개합니다. 1.5초 이상 회전을 확인하지 못하면 손등을 다시 카메라 쪽으로 펴고 잠깐 유지해야 방향이 복구됩니다. 옆면에서 잘못된 앞뒤 방향을 선택해 계속 도는 일을 줄이기 위한 보수적인 처리입니다.
- 손바닥을 보였다가 실제로 되돌리는 동작은 여러 프레임의 3D 방향 증거로 확인합니다. 회전 예측만으로 한 방향 회전을 강제하지 않습니다.
- 추적 대상이 복구되지 않으면 같은 손을 원래 위치로 가져오거나 **손등 기준 맞추기**를 누르세요. 이 버튼은 추적할 손과 회전 기준을 함께 다시 선택합니다. 다른 손으로 바꿀 때도 사용합니다.
- 진단 JSON에 선택한 손의 인덱스·검출 수·대상 상태·회전 기억의 경과 시간을 추가했습니다. 최대 두 손 추론에 따른 기기별 처리 시간 변화는 휴대폰에서 확인해야 합니다.

33개 자동 검사에는 검출 순서 변경, 배경 손 거부, 좌우 손 변경, 손 겹침, 누락 후 잘못된 깊이값, 긴 가림 후 복구, 실제 회전 반전이 포함됩니다. 개인 화면 녹화의 로컬 재추론에서도 끝부분의 배경 손 검출 3회를 거부하고 시계를 숨기는 것을 확인했습니다. 실제 Android의 원본 입력에 대한 정확도 보장은 아닙니다.

## 0.4 화면 관절 배치로 회전 보정

- 손등 기준 설정 때 최소 0.5초·6회 이상의 일관된 관측으로 손바닥 평면의 기준 형태를 만듭니다. 모델의 프레임별 뼈 길이 대신 화면에서 관측한 기준 형태를 사용합니다.
- 매 프레임 손목·네 손가락 뿌리를 기준 형태에 맞추어 투영 변화를 계산합니다. 화면상 손 폭과 관절 배치로 기울기 크기를 구하고, 추정 3D 깊이와 이전 방향으로 앞뒤 깊이의 모호성을 풉니다. 각도 상한은 없으며 양방향 전체 회전을 허용합니다.
- 배치 오차가 크면 회전을 잠깐 유지하고, 220ms 이상 확신할 수 없으면 시계를 숨깁니다. 진단의 ‘배치 일치도’는 이 기하학적 일관성을 뜻하며 실제 정확도 점수가 아닙니다.
- 기준 손 폭과 투영 배율로 시계 크기·손목 반경을 계산하여 모델의 추정 뼈 길이 변화가 크기에 바로 반영되는 것을 줄입니다.
- 회전의 중복 보간을 없애고 추론 요청 시각을 기준으로 결과의 나이를 판단합니다. 표시되는 회/초는 추론 실행 횟수입니다.
- **관절·회전 진단 → 진단 표시·좌표 기록**을 켜면 손 관절, 원래 3D 방향, 보정 방향과 처리 시간이 표시됩니다. **진단 기록 저장**은 최근 600회의 좌표·설정·처리 시간을 JSON으로 기기에 저장합니다. 영상이나 모델은 포함하지 않으며 자동 업로드하지 않습니다.

손목 윤곽이나 팔을 직접 인식하는 기능은 아직 없습니다. 약한 원근 투영의 평면 근사이므로 손목 꺾임, 손가락 가림, 큰 원근 왜곡에서 오차가 남을 수 있습니다. 화면 녹화 재분석은 이미 AR이 합성되고 화면이 잘린 영상을 다시 추론하는 것이므로 폰의 원본 추적 결과나 실제 각도 정답과 같지 않습니다.

## 0.3에서 유지한 회전 처리

- 엄지의 CMC·MCP 관절(1·2)과 새끼손가락 MCP(17)의 3D 위치 차이를 검지·중지·약지 뿌리 및 손목과 함께 사용합니다. 손가락 끝을 벌리는 동작은 회전 계산에 넣지 않습니다.
- 손등 기준을 처음 한 번 정하고 추적 누락 후에도 유지합니다. 0.2의 약 49~54도 기울기 제한과 옆면에서의 각도 고정을 제거했습니다. 손등 → 옆면 → 손바닥 방향으로 연속 회전할 수 있습니다.
- 첫 인식은 손등을 보여 주는 사용 조건에 의존합니다. 손바닥으로 시작하거나 다른 손으로 바꾸면 **손등 기준 맞추기**가 필요할 수 있습니다. 자동 손바닥/손등 분류 기능은 아닙니다.
- 시계가 손목 중심을 축으로 돌도록 수정했습니다. 손바닥이 보이는 자세에서는 시계 본체가 손목 뒤에 가려질 수 있습니다. 시계 크기를 바꿔도 추정 손목 반경은 유지합니다.
- 회전 전체를 제한하는 대신 한 프레임만 발생하는 큰 각도 이상값을 걸러내고 quaternion으로 보간합니다.

## 0.2에서 유지한 안정화

- 손목과 네 손가락의 시작 관절을 함께 사용합니다.
- 움직이는 속도에 따라 위치 보정 강도를 조절하고 크기 변화와 순간적인 위치 튐을 완화합니다.
- 짧은 누락은 최대 220ms 유지하고, 그 뒤에도 손을 찾지 못하면 시계를 숨깁니다.
- 가능한 브라우저에서는 Web Worker에서 추적합니다. 처리 중인 프레임을 쌓지 않으며 입력의 긴 변은 최대 640픽셀로 줄입니다. Worker를 사용할 수 없으면 기존 스레드에서 동작합니다.
- 기기 성능에 따라 최대 30회/초를 목표로 추적합니다. 실제 속도는 화면에 표시되며 기기마다 다릅니다.

## 모델 준비

- glTF 2.0 `.glb`로 내보내며 텍스처와 데이터를 파일 안에 포함합니다.
- 초기 권장 목표는 5~10MB 이하, 텍스처 1K~2K입니다. 파일 선택 상한은 40MB입니다.
- 본체·유리·스트랩을 분리해 두면 후속 조정에 편리합니다.
- 케이스 지름·두께·스트랩 폭을 mm로 함께 준비합니다. 현재 크기 조절은 실제 치수 측정 기능이 아닙니다.
- 좌표 기준: X는 케이스 좌우, Y는 다이얼 12시·6시와 스트랩 방향, +Z는 다이얼 앞면입니다. 피부 접촉면을 Z=0으로 두면 맞추기 쉽습니다.
- X축 전체 너비를 기준으로 정규화하고 X/Y 중심은 가운데 맞추며 Z 원점은 유지합니다.
- 스트랩은 손목을 감싸는 착용 형태로 모델링합니다. 펼쳐진 스트랩을 자동으로 구부리지는 않습니다.
- 기본 시계 회전은 90°입니다. 모델에 따라 방향·높이 설정을 조절합니다.
- Draco 압축은 지원합니다. KTX2/BasisU와 Meshopt 압축은 끄고 내보내 주세요.

## 로컬 개발

Node.js 20 이상이 필요합니다.

```sh
npm ci
npm start
```

PC에서 http://localhost:4173 을 엽니다. `npm start`가 버전이 고정된 라이브러리와 공식 추적 모델을 `vendor/`에 준비합니다. 모델 파일은 SHA-256 해시를 검사합니다.

```sh
npm test
npm run build
```

`dist/`가 HTTPS 호스팅용 결과물입니다. GitHub Actions가 main 브랜치에 변경 사항이 반영될 때 테스트·빌드 후 GitHub Pages로 배포합니다. Pages 설정의 배포 Source는 **GitHub Actions**입니다.

휴대폰에서 로컬 개발 서버를 보려면 USB 포트 전달을 사용합니다. ADB가 설치된 PC에서는 `adb reverse tcp:4173 tcp:4173` 실행 후 휴대폰 Chrome에서 http://localhost:4173 을 엽니다. 같은 Wi-Fi의 일반 HTTP IP 주소는 카메라 보안 조건을 만족하지 않습니다.

## 현재 한계와 검증

단일 RGB 카메라의 손 관절을 사용한 시각적 추정입니다. 손목 둘레나 실제 시계 크기를 측정하지 않습니다. 손등이 보이는 자세에 맞춘 초기 버전이며 손바닥/손등을 자동 분류하지 않습니다. 큰 회전, 빠른 움직임, 손가락 가림에서 어긋날 수 있습니다.

가림 처리는 보이지 않는 타원형 손목 모형을 사용합니다. 정밀한 피부 분할, 소매나 다른 물체에 의한 가림, 접촉 그림자, 환경 반사, 스트랩 자동 변형은 구현하지 않았습니다. 팔 자체의 방향은 추적하지 않으므로 손목을 크게 꺾으면 손 방향과 팔 방향이 달라져 어긋날 수 있습니다.

단위 검사와 데스크톱 Chromium에서 모바일 화면, GLB 교체, 권한 거부 후 복구, 실제 MediaPipe 모델에 테스트 손 영상을 입력하는 추적, 손이 사라질 때 숨김, 카메라 스트림 종료를 확인했습니다. 실제 Android 기기에서의 추적 정확도와 속도는 별도 검증이 필요합니다.

0.2에서는 깊이 이상값, 옆면 자세, 누락·재검출, 위치 튐, 정지 흔들림과 이동 지연의 회귀 검사를 추가했습니다. 화면 녹화를 로컬에서 재분석해 이전 자세 계산과 비교했습니다. 화면 녹화에는 기존 AR 오버레이가 포함되어 있으므로 원본 카메라 영상이나 실제 위치 정답에 대한 정확도 평가와는 다릅니다. 검증용 개인 영상은 저장소와 배포에 포함하지 않습니다.

0.3 회귀 검사는 합성 3D 관절의 양쪽 90도·전체 회전, 좌우 손, 전면 미러링, 손가락 끝만 움직이는 경우, 순간적인 180도 이상값, 재검출 때 기준 방향 유지, 손목 회전 중심 유지 등을 포함합니다. 0.4는 여러 축의 투영 복원, 틀린 3D 깊이에 대한 보정, 좌우 손·미러링에서 양방향 전체 회전, 관절 배치 불일치 시 만료·복귀, 뼈 길이 변화와 크기·확대 구분, 오래된 결과 거부, 시간 기반 기준 설정을 추가했습니다. 이 검사는 계산의 방향·연속성을 검증하며 실제 카메라의 관절 추정 정확도를 보장하지 않습니다. 손 관절의 깊이 추정 오류나 손목과 팔 사이의 꺾임은 여전히 오차 원인입니다.

## 구현과 출처

[VeinSyct/Wrist-AR](https://github.com/VeinSyct/Wrist-AR)의 카메라 → 손 추적 → 시계 정렬 흐름을 참고한 **독립 구현**입니다. 원본 저장소를 수정한 포크는 아닙니다.

원본 검토 커밋은 `b21e71ae69edeafab22da277b27f4b8282254bb2`입니다. 원본의 public 코드는 MediaPipe를 사용하지만, dist의 SDK 메타데이터는 DeepAR 5.6.19를 선언합니다. 이 프로젝트는 해당 SDK·키·인코딩된 코드·브랜드 시계 모델을 포함하지 않습니다.

## 주요 파일

- `app.js`: 카메라, 렌더링, GLB 불러오기, UI
- `pose.js`: 화면 좌표와 손목 위치·방향 추정

- `wrist-rig.js`: 타원형 손목 모형, 맞춤 스트랩, 본체 접촉 위치와 가림
- `index.html`, `style.css`: 모바일 화면
- `prepare-assets.mjs`, `build.mjs`: 실행 파일 준비·빌드
- `core.test.mjs`: 좌표 변환과 GLB 검사
